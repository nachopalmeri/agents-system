# Scoped worker development

Delegate meaningful independent units, not every plan checkbox. Follow runtime model routing: smallest reliable native model or verified-free OpenCode, with primary synthesis and validation. Never claim a worker/model invocation that did not occur.

1. Identify the critical-path task for the primary and independent sidecars for workers. Assign disjoint file ownership; never duplicate delegated work.
2. Send objective, acceptance criteria, exact paths/exclusions, essential context pointers and required checks. Start without inherited full history. Max three concurrent workers, depth one; no worker may spawn another.
3. Implementers test relevant behavior before changing implementation when TDD applies. They return DONE, DONE_WITH_CONCERNS, NEEDS_CONTEXT or BLOCKED with changed paths, evidence and blockers—not full files/logs. Do not commit/publish unless specifically authorized.
4. Primary inspects each diff and acceptance evidence, then performs one combined spec/quality review at a meaningful checkpoint. Separate spec and quality reviewers only for demonstrated risk, independent expertise or explicit request; no automatic two-stage review per task or unconditional final council.
5. Resolve important findings and run affected checks. One corrective pass, then replan or report a blocker if unchanged failure repeats. Do not force retries, broaden permissions or select paid fallback.

Keep review proportional, not optional: worker self-review cannot approve its own integration; primary remains accountable. Architecture/risk may need a stronger model, routine reviews need not. Read `../code-review/SKILL.md` for a material review, and only its relevant template if a reviewer is dispatched.

## Sin subagentes o en otra sesión

Execute dependency-ready tasks in the current session with compact checkpoints and relevant validation. For substantial session transitions use `../../workflows/ticket_sessions.md`; no new user chats/messages without explicit authorization. If a detailed cross-session procedure is needed, read `references/executing-plans/GUIDE.md`, subject to these lean defaults and runtime permissions.
